## ทีมสองบอท (2 บัญชี Claude ช่วยกันพัฒนา {{NAME}})
รายละเอียดเต็ม: สกิล `two-bot-dev` (ขั้นตอนทำงาน/รีวิว/CF) และ `two-bot-setup` (ตั้งค่าบอท/แก้ปัญหา)

### ตั้งค่า
- บอทแต่ละตัวทำงานใน **git worktree ของตัวเอง** (`../{{NAME}}-bot1`, `../{{NAME}}-bot2`) — ชื่อบอทอยู่ใน env `PS_BOT`
- ไฟล์ทีมใช้ร่วมกัน (ไม่อยู่ใน git): `{{TEAM_DIR}}\BOARD.md` (ใครทำอะไร), `{{TEAM_DIR}}\LOG.md` (บันทึกร่วม), `{{TEAM_DIR}}\heavy.lock`
- บอทมองไม่เห็นข้อความของกันใน Discord (allowlist มีแค่ผู้ใช้ — ห้ามเพิ่ม ID บอท เสี่ยงตอบกันวน) → คุยกันผ่านไฟล์ทีมเท่านั้น

### กฎทำงานร่วมกัน (ทำทุกงาน ห้ามข้าม)
1. **เริ่มงาน**: อ่าน LOG ตั้งแต่ครั้งล่าสุดที่ตัวเองอ่าน → ติ๊ก `รับทราบ` ที่ค้างของตัวเอง → `git fetch` แล้ว merge `main` เข้าที่ทำงานของตัวเอง
   → อ่าน CLAUDE.md ใหม่ (session ที่เปิดค้างไม่เห็นฉบับแก้) → ดู BOARD: งาน/branch/ไฟล์ที่อีกบอทจองไว้ = ห้ามแตะ บอกผู้ใช้ · ไม่ชน = จองแล้วค่อยเริ่ม
2. **branch**: ทำทุกอย่างบน `bot1/<ฟีเจอร์>` หรือ `bot2/<ฟีเจอร์>` ที่แตกจาก `main` ล่าสุด — **ห้าม commit โค้ดตรงเข้า main, ห้าม force push, ห้ามแก้ branch ของอีกบอท**
3. **ก่อนส่งงาน**: เทสต์/lint/build ของโปรเจกต์ต้องผ่าน (ไม่มีเทสต์ = เขียนเพิ่มหรือบอกผู้ใช้ตรงๆ ว่ายังไม่ได้ทดสอบอะไร)
   → commit (`[botN] <อะไร>`) → push branch ของตัวเอง → แจ้งผู้ใช้ใน Discord: สรุปสั้น + ลิงก์ compare/PR + วิธีทดสอบ
4. **รีวิว**: ผู้ใช้แท็กบอทเดียวต่องาน; ถ้าแท็กทั้งคู่เรื่องเดียวกัน **บอท 1 = คนทำ, บอท 2 = คนตรวจ** — คนตรวจอ่านอย่างเดียว
   (`git diff main...origin/botN/<ฟีเจอร์>`, รันเทสต์ใน worktree ตัวเอง) แล้วรายงานผู้ใช้ + ลง LOG ว่า `ตรวจ:` · ข้อเสนอแก้ผ่านผู้ใช้ ไม่แก้ branch ของคนทำเอง
5. **merge เข้า main**: เฉพาะเมื่อผู้ใช้อนุมัติเท่านั้น (`--no-ff`); ผู้ใช้สั่งบอทตัวไหน ตัวนั้นทำ แล้วลง LOG
6. **งานหนัก**: build ใหญ่/เทสต์ชุดยาว/ดาวน์โหลด ทั้งสองบอทรวมกันได้ทีละงาน — มี `heavy.lock` = รอ; ไม่มี = สร้าง (บอท+งาน+เวลา) แล้วรัน ลบเมื่อจบหรือโดนหยุด
7. **จบงาน/หยุด/โควตาจะหมด**: เขียนรายการต่อท้าย LOG ตามแบบในไฟล์ → ลบการจองใน BOARD · งานค้างที่อีกตัวต้องทำต่อ = push branch + handoff
8. **ทดลอง ≠ นโยบาย**: ลองวิธี/ไลบรารีใหม่บน branch `botN/try-<อะไร>` ได้เต็มที่ ขึ้นต้น LOG ว่า `ทดลอง:` — เป็นนโยบายได้เมื่อผู้ใช้อนุมัติเท่านั้น
9. **นโยบายมีที่เดียว**: CLAUDE.md + `.claude/skills/` ของ repo นี้ (+ config เทสต์/lint) — แก้ได้ทีละบอท: จอง `นโยบาย` ใน BOARD →
   commit เฉพาะไฟล์นโยบายเข้า `main` ได้ตรงเมื่อผู้ใช้สั่งหรืออนุมัติแล้ว (`[botN] policy: …`) → push → LOG พร้อม `รับทราบ: botX ☐` → แจ้งผู้ใช้
   ผู้ใช้สั่งผ่านบอทไหนก็ตาม อีกตัวต้องรับทราบเสมอ (ข้อ 1)
10. **"CF" = Close Feature** (ผู้ใช้พิมพ์ `CF` หรือ `CF <ฟีเจอร์>`): สรุปทุกอย่างที่ผู้ใช้สั่งแก้/ติ/ชมระหว่างทำฟีเจอร์ → แยกถาวร/เฉพาะงาน →
   อัปเดตกฎให้ถูกที่ (แก้กฎเก่าที่ขัด ไม่กองท้ายไฟล์) → รายงาน "CF <ฟีเจอร์> — กฎใหม่ N ข้อ" → merge (ถ้าผู้ใช้อนุมัติ) → ลบ branch → LOG `CF:` + รับทราบ
11. **ข้อผิดพลาดทุกครั้ง**: บันทึกสาเหตุ+วิธีกันใน LOG ภายในวันนั้น ถ้ากันด้วยโค้ด/เทสต์ได้ให้ทำแทนการพึ่งความจำ · ก่อนบอกว่า "เสร็จ/ผ่าน" ต้องมีผลรันจริงในมือ
12. **ห้ามเด็ดขาด**: commit/push token, `.env`, รหัสผ่าน, ข้อมูลส่วนตัว · push ไป main โดยผู้ใช้ไม่อนุมัติ · ลบ branch/ไฟล์ของอีกบอท
