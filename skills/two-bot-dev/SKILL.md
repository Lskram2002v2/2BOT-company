# บอทคู่พัฒนาแอป (two-bot-dev)

กฎสั้นอยู่ใน CLAUDE.md หัวข้อ "ทีมสองบอท" (โหลดทุก session) — สกิลนี้คือวิธีทำทีละขั้น
ตัวแปร: `PS_BOT` = ชื่อตัวเอง (bot1/bot2), `TEAM_DIR` = โฟลเดอร์ไฟล์ทีม (BOARD.md, LOG.md, heavy.lock) — ทั้งคู่ตั้งใน launcher

## 1. รับงาน (ทุกงาน)
```bash
echo "$PS_BOT $TEAM_DIR"
git fetch --all --prune
```
1. อ่าน `$TEAM_DIR/LOG.md` ตั้งแต่รายการล่าสุดที่ตัวเองเขียนหรือติ๊ก → มี `รับทราบ: <ตัวเอง> ☐` = อ่านกฎที่เปลี่ยน (CLAUDE.md / สกิล ที่ระบุ) ให้จบ แก้เป็น `☑ HH:MM`
2. `git merge origin/main` เข้า branch ที่ทำอยู่ (หรือ `git switch --detach origin/main` ถ้าไม่มีงานค้าง) → อ่าน CLAUDE.md ใหม่ด้วย Read
3. อ่าน `$TEAM_DIR/BOARD.md` — งาน/branch/ไฟล์ที่ชนกับอีกบอท = หยุด ถามผู้ใช้ใน Discord ("บอท 2 กำลังแก้ X อยู่ จะให้รอหรือแบ่งยังไง")
4. ไม่ชน → เพิ่มบรรทัดจอง: `| bot1 | <งาน> | bot1/<feature>, src/foo/* | HH:MM | ทำ |`
5. ตอบผู้ใช้สั้นๆ ว่ารับงานแล้ว + จะทำอะไร (ถ้างานใหญ่/กำกวม ถามก่อนเริ่ม ไม่เดา)

## 2. ทำงาน
- `git switch -c <PS_BOT>/<feature-สั้น-ascii> origin/main` — ชื่อ branch บอกว่าของใคร
- แก้เฉพาะไฟล์ที่จอง ต้องแตะไฟล์เพิ่มที่อีกบอทจอง = ถามผู้ใช้ก่อน
- commit ถี่ ข้อความ `[bot1] <ทำอะไร>` · `git add <ไฟล์>` ระบุทีละไฟล์ ห้าม `git add -A` · ห้าม commit `.env`/token/ไฟล์ใหญ่
- งานหนัก (build ใหญ่/เทสต์ยาว): `test -e "$TEAM_DIR/heavy.lock"` มี = รอ/บอกผู้ใช้; ไม่มี = `echo "$PS_BOT <งาน> $(date +%H:%M)" > "$TEAM_DIR/heavy.lock"` → รัน → `rm` เมื่อจบหรือล้ม
- เวลาเกิน ~1 ชม. หรือโควตาใกล้หมด: push branch + LOG `ค้าง/ต่อ:` ไว้ก่อน (อีกบอทจะได้รับต่อได้)

## 3. ส่งงาน
1. รันเทสต์/lint/build ของโปรเจกต์ (ดูคำสั่งใน README/package.json/Makefile) — ต้องผ่านจริง; ไม่มีเทสต์ = เพิ่มเทสต์ให้ส่วนที่แก้ หรือบอกตรงๆ ว่ายังไม่ได้ทดสอบอะไร
2. `git push -u origin <branch>` (branch ของตัวเองเท่านั้น ห้าม force push)
3. แจ้งผู้ใช้ใน Discord: ทำอะไร (2–4 บรรทัด), ลิงก์ `https://github.com/<owner>/<repo>/compare/main...<branch>` (หรือ PR ถ้ามี `gh`), วิธีลองเอง, ผลเทสต์
4. LOG รายการใหม่ (แบบในไฟล์) · BOARD: เปลี่ยนสถานะเป็น "รอรีวิว" (ยังไม่ลบจนกว่าจะ merge/ทิ้ง)

## 4. รีวิว (บอทที่ได้บทบาท "ตรวจ")
- อ่านอย่างเดียว: `git fetch && git diff origin/main...origin/<branch>`, รันเทสต์ใน worktree ตัวเอง (`git switch --detach origin/<branch>`)
- เช็ก: ทำตามที่ผู้ใช้สั่งครบไหม, บั๊ก/edge case, เทสต์ครอบคลุม, ขัดกับกฎใน CLAUDE.md/สกิลไหม, ไฟล์ลับหลุดไหม
- รายงานผู้ใช้: ✅ ผ่าน หรือ รายการปัญหา (ไฟล์:บรรทัด + เหตุผล + ข้อเสนอ) — **ไม่แก้ branch ของคนทำเอง** ผู้ใช้จะสั่งคนทำแก้
- LOG `ตรวจ: <branch>` + ผล

## 5. merge (เฉพาะเมื่อผู้ใช้อนุมัติ เช่น "merge ได้", "ผ่าน รวมเลย")
```bash
git switch --detach origin/main && git merge --no-ff origin/<branch> -m "[botN] merge <branch>"
# รันเทสต์อีกรอบบนผลรวม → ผ่านค่อย push
git push origin HEAD:main
git push origin --delete <branch>
```
ชนกัน (conflict) = แก้ถ้าชัดเจน ไม่ชัด = หยุดถามผู้ใช้ · merge แล้ว: ลบการจองใน BOARD + LOG + บอกอีกบอทผ่าน LOG ให้ merge main

## 6. แก้นโยบาย (ผู้ใช้สั่ง "ต่อไปให้…", "ห้าม…", "ใช้แบบนี้ทุกครั้ง")
1. จอง `นโยบาย` ใน BOARD (อีกบอทจองอยู่ = รอ)
2. แก้ให้ถูกที่: กฎสั้นที่ต้องรู้ทุกงาน → CLAUDE.md · วิธีทำละเอียด → สกิลใน `.claude/skills/` · กันด้วยเครื่องมือได้ → config lint/test/hook
   **กฎเก่าที่ขัดกันต้องแก้/ลบ** ไม่ให้มีสองแบบ
3. commit เฉพาะไฟล์นโยบายตรงเข้า main: `git switch --detach origin/main` → แก้ → `git commit -m "[botN] policy: …"` → `git push origin HEAD:main`
4. LOG: `นโยบาย: เปลี่ยน … เพราะ …` + `รับทราบ: <อีกบอท> ☐` → ปลดจอง → แจ้งผู้ใช้ "นโยบายเปลี่ยน: …"

## 7. CF = Close Feature (ผู้ใช้พิมพ์ `CF` หรือ `CF <feature>`) — หัวใจคือ "เรียนรู้"
ไม่ระบุ = ฟีเจอร์ที่ตัวเองจองใน BOARD; ไม่แน่ใจ = ถาม
1. รวบรวมทุกครั้งที่ผู้ใช้สั่งแก้/ติ/ชม ในฟีเจอร์นี้: แชท, LOG ทุกรายการของฟีเจอร์ (ทั้งสองบอท), ผลรีวิว, ข้อผิดพลาดที่เกิด
2. ตาราง: | ผู้ใช้สั่ง/เกิดอะไร | ถาวร หรือ เฉพาะงาน | ใส่กฎที่ไหน | ข้อความกฎ | — ที่ผู้ใช้สั่งตรงๆ เป็นกฎได้เลย; ที่บอทสรุปเอง = "เสนอ" รออนุมัติ
3. อัปเดตกฎตามข้อ 6 (ใส่ถูกที่ แก้ของเก่าที่ขัด)
4. ถ้าผู้ใช้อนุมัติ merge แล้ว → ข้อ 5; ยัง = ถาม
5. รายงาน: "CF <feature> — merge แล้ว/ยัง · กฎใหม่ N ข้อ: … · รอยืนยัน: …" → LOG `CF:` + `รับทราบ: <อีกบอท> ☐` → ลบการจอง

## 8. ส่งต่องาน (handoff)
บอทหยุด/ติดลิมิต: push branch → LOG `ค้าง/ต่อ:` (ทำถึงไหน, ขั้นต่อไป, ไฟล์ที่เกี่ยว) → เปลี่ยนเจ้าของใน BOARD เป็น `รอคนรับ`
ผู้ใช้สั่งอีกบอท "ทำต่อจาก botN" → อ่าน LOG → เปลี่ยน BOARD เป็นชื่อตัวเอง → `git switch -c <ตัวเอง>/<feature> origin/<branch เดิม>` (ไม่แก้ branch ของอีกบอทโดยตรง)

## ข้อห้าม
push main โดยไม่ได้รับอนุมัติ · force push · แก้/ลบ branch หรือไฟล์ที่อีกบอทจอง · commit ความลับ · บอก "เสร็จ/ผ่าน" โดยไม่มีผลรันจริง ·
เพิ่ม ID บอทใน allowlist ของ Discord · ตั้งนโยบายเองจากความเห็นตัวเองโดยไม่บอกผู้ใช้
